# 투표 앱 v1 스펙

Status: ready-for-agent

## Problem Statement

동아리 회장은 구성원에게 결정을 물을 방법이 필요하다. 지금은 채팅방에서 손을 들게 하거나 댓글로 세는데, 집계가 번거롭고 여러 안건을 동시에 묻기 어렵다. 회장은 "질문 하나 올리면 사람들이 선택지 중 하나를 골라서 투표하고, 결과를 볼 수 있으면 된다"고 요청했다.

## Solution

운영자가 공유 비밀번호로 로그인해 투표를 만들고 삭제하는 웹앱을 만든다. 투표자는 로그인 없이 첫 화면에서 진행 중인 투표 목록을 보고, 투표 하나를 골라 선택지 하나에 투표한다. 투표하면 바로 결과 화면으로 이동해 선택지별 득표수, 비율, 총 투표 수를 보고, 결과는 5초마다 자동으로 갱신된다. 결과는 그 투표에 참여한 투표자와 운영자만 볼 수 있다. 여러 투표가 동시에 열려 있을 수 있다. (v1.1: 투표에는 최대 7일의 마감 시각이 있고, 마감되면 결과가 모두에게 공개된다. 아래 "v1.1 추가 기능" 참고)

## User Stories

### 투표자 — 목록과 투표

1. 투표자로서, 첫 화면에서 진행 중인 모든 투표 목록을 보고 싶다. 그래야 참여할 투표를 찾을 수 있다.
2. 투표자로서, 목록에서 투표마다 질문을 보고 싶다. 그래야 무엇을 묻는 투표인지 알 수 있다.
3. 투표자로서, 목록이 최신 투표부터 보이면 좋겠다. 그래야 새로 올라온 투표를 바로 찾을 수 있다.
4. 투표자로서, 진행 중인 투표가 없을 때는 "진행 중인 투표가 없습니다" 안내를 보고 싶다. 그래야 화면이 고장 난 게 아니라는 걸 안다.
5. 투표자로서, 목록에서 투표를 누르면 그 투표의 투표 화면으로 가고 싶다. 그래야 바로 투표할 수 있다.
6. 투표자로서, 로그인 없이 투표하고 싶다. 그래야 번거로운 가입 없이 참여할 수 있다.
7. 투표자로서, 투표 화면에서 질문과 모든 선택지를 보고 싶다. 그래야 고를 수 있다.
8. 투표자로서, 선택지 중 정확히 하나만 고를 수 있으면 좋겠다. 그래야 한 사람의 뜻이 하나로 집계된다.
9. 투표자로서, 아무것도 고르지 않고 제출하면 막히고 싶다. 그래야 실수로 빈 표를 내지 않는다.
10. 투표자로서, 제출하면 바로 그 투표의 결과 화면으로 가고 싶다. 그래야 내 표가 반영된 결과를 확인할 수 있다.
11. 투표자로서, 이미 투표한 투표를 다시 열면 투표 화면 대신 결과 화면으로 가고 싶다. 그래야 헷갈리지 않는다.
12. 투표자로서, 같은 브라우저에서 같은 투표에 다시 투표하려 하면 막히고 결과 화면으로 가고 싶다. 오래된 화면에서 다시 제출한 경우도 마찬가지다. 그래야 실수로 두 번 투표하지 않는다.
13. 투표자로서, 없거나 삭제된 투표의 주소로 들어가면 "투표를 찾을 수 없습니다" 안내를 보고 싶다. 그래야 무슨 일인지 안다.
14. 투표자로서, 투표하는 사이에 그 투표가 삭제되면 오류 대신 "투표를 찾을 수 없습니다" 안내를 보고 싶다.
15. 투표자로서, 여러 투표에 각각 한 번씩 투표할 수 있으면 좋겠다. 그래야 동시에 열린 여러 안건에 모두 참여할 수 있다.

### 투표자 — 결과

16. 투표자로서, 결과 화면에서 선택지별 득표수를 보고 싶다.
17. 투표자로서, 결과 화면에서 선택지별 비율(%)을 보고 싶다. 그래야 한눈에 비교할 수 있다.
18. 투표자로서, 결과 화면에서 총 투표 수를 보고 싶다.
19. 투표자로서, 결과 화면을 보고 있는 동안 새로고침하지 않아도 숫자가 최신으로 바뀌면 좋겠다(5초 간격). 그래야 진행 상황을 지켜볼 수 있다.
20. 투표자로서, 아직 투표하지 않은 투표의 결과는 볼 수 없어야 한다. 결과 주소를 직접 입력해도 투표 화면으로 보내져야 한다. 그래야 결과를 보고 따라 찍는 일이 줄어든다.
21. 투표자로서, 결과 화면에서 목록으로 돌아가는 링크가 있으면 좋겠다.
21-1. 투표자로서, 결과 화면에서 내가 고른 선택지가 초록색과 "✓ 내 선택"으로 표시되면 좋겠다. 그래야 내 표가 어디에 들어갔는지 확인할 수 있다.

### 운영자 — 로그인

22. 운영자로서, 공유 비밀번호로 로그인하고 싶다. 그래야 투표를 관리할 수 있다.
23. 운영자로서, 비밀번호가 틀리면 오류 안내를 보고 싶다.
24. 운영자로서, 한 번 로그인하면 1일 동안 다시 입력하지 않아도 되면 좋겠다.
25. 운영자로서, 1일이 지나면 다시 로그인하도록 요구받아야 한다. 그래야 공용 PC에 로그인이 오래 남지 않는다.
26. 운영자로서, 로그아웃 버튼으로 직접 로그아웃하고 싶다.
27. 운영자로서, 로그인하지 않은 사람이 운영자 화면에 들어오면 로그인 화면으로 보내지면 좋겠다. 그래야 아무나 투표를 만들거나 지우지 못한다.
28. 운영자로서, 로그인하지 않은 사람이 화면을 거치지 않고 투표 생성·삭제를 직접 요청해도 거부되면 좋겠다.

### 운영자 — 투표 만들기

29. 운영자로서, 질문 하나와 선택지를 입력해 투표를 만들고 싶다.
30. 운영자로서, 선택지 입력칸을 추가하거나 빼면서 2~10개를 입력하고 싶다.
31. 운영자로서, 선택지가 2개 미만이거나 10개를 넘으면 만들기가 거부되고 이유를 보고 싶다.
32. 운영자로서, 질문이 비었거나 빈 선택지가 있으면 만들기가 거부되고 이유를 보고 싶다.
33. 운영자로서, 화면을 거치지 않은 요청이라도 규칙(질문 필수, 선택지 2~10개, 빈 선택지 없음)이 서버에서 똑같이 지켜지면 좋겠다.
34. 운영자로서, 만든 투표가 즉시 첫 화면 목록에 나타나면 좋겠다.
35. 운영자로서, 투표를 여러 개 동시에 열어 둘 수 있으면 좋겠다.

### 운영자 — 관리와 삭제

36. 운영자로서, 운영자 화면에서 모든 투표 목록과 각 투표의 총 투표 수를 보고 싶다.
37. 운영자로서, 투표하지 않아도 모든 투표의 결과를 언제든 보고 싶다. 그래야 삭제 여부를 판단할 수 있다.
38. 운영자로서, 투표를 삭제하고 싶다.
39. 운영자로서, 삭제 전에 "정말 삭제할까요?" 확인을 한 번 받고 싶다. 그래야 실수로 지우지 않는다.
40. 운영자로서, 투표를 삭제하면 그 선택지와 받은 표가 모두 함께 영구 삭제되면 좋겠다.
41. 운영자로서, 삭제한 투표가 첫 화면 목록과 운영자 목록에서 즉시 사라지면 좋겠다.
42. 운영자로서, 만든 투표는 수정할 수 없다는 걸 알고 있다. 고치고 싶으면 삭제하고 새로 만든다.

### 개발자·배포

43. 개발자로서, `npm run dev` 하나로 로컬에서 앱 전체를 실행하고 싶다.
44. 개발자로서, 비밀 값(DB 연결 문자열, 운영자 비밀번호, 세션 서명 키)을 코드가 아닌 `.env.local`에만 두고 싶다. 그래야 GitHub에 올라가지 않는다.
45. 개발자로서, 같은 환경변수를 Vercel 프로젝트 설정에 넣기만 하면 배포본이 그대로 동작하면 좋겠다.
46. 개발자로서, 테이블을 만드는 SQL을 파일로 받아 Neon SQL Editor에서 직접 실행하고 싶다.

## Implementation Decisions

- **기술 스택:** Next.js(App Router) + TypeScript + Neon Postgres(`@neondatabase/serverless`). ORM 없이 raw SQL을 쓴다. 이 저장소의 Next.js 버전은 학습 데이터와 다를 수 있으므로, 구현 전에 `node_modules/next/dist/docs/`의 해당 가이드(Route Handlers, Proxy, Authentication, Forms 등)를 확인한다.
- **실행과 배포:** 로컬은 `npm run dev`, 배포는 Vercel이다. 사전 준비에서 만든 Neon DB 하나를 로컬과 배포에서 함께 쓴다. 로컬 전용 설정이나 별도 서버 프로세스는 두지 않는다.
- **환경변수:** 세 가지를 쓴다. `.env.local`과 Vercel 프로젝트 환경변수에 같은 이름으로 둔다.
  - `DATABASE_URL`: Neon 연결 문자열
  - `OPERATOR_PASSWORD`: 운영자 공유 비밀번호
  - `SESSION_SECRET`: 운영자 세션 쿠키 서명 키
- **스키마:** 투표와 선택지 두 테이블이다. 선택지가 자기 득표수를 가진다. 쿠키로 중복을 막으므로(ADR-0001) 투표 행위를 개별 행으로 저장하지 않는다. 테이블 생성 SQL은 저장소의 SQL 파일로 두고, Neon SQL Editor에서 사람이 직접 실행한다.
  - polls: id(uuid, 기본값 자동 생성), question(text, 필수), created_at(timestamptz, 기본값 now)
  - options: id(uuid), poll_id(polls 참조, **on delete cascade**), label(text, 필수), position(정수, 입력 순서 유지용), vote_count(정수, 기본값 0)
- **DB 접근 모듈:** 투표 도메인 동작을 한 모듈에 모은다. 화면과 API는 SQL을 직접 쓰지 않고 이 모듈만 호출한다.
  - 투표 목록 조회(최신순), 투표와 선택지 조회, 투표 생성(질문 + 선택지 검증 포함), 투표 행위 기록(득표수 +1, 해당 투표의 선택지인지 확인), 결과 조회(득표수·비율·총 투표 수), 투표 삭제
  - 득표수 증가는 `vote_count = vote_count + 1` 한 문장으로 처리해 동시 투표에도 값이 꼬이지 않게 한다.
  - 투표 생성은 투표 행과 선택지 행이 함께 들어가야 한다. 일부만 저장되는 일이 없도록 한다.
- **입력 검증:** 질문 필수, 선택지 2~10개, 빈 선택지 없음. 앞뒤 공백을 제거한 뒤 검사한다. 화면과 서버 양쪽에서 검사하며, 서버 검사가 기준이다.
- **페이지:**
  - `/`: 진행 중인 투표 목록(최신순)
  - `/polls/[id]`: 투표 화면. 이미 투표한 브라우저는 결과 화면으로 보낸다.
  - `/polls/[id]/results`: 결과 화면. 투표하지 않은 투표자는 투표 화면으로 보낸다. 운영자는 항상 볼 수 있다.
  - `/login`: 운영자 로그인
  - `/operator`: 운영자 투표 목록(총 투표 수 포함), 삭제 버튼(확인 단계 포함), 로그아웃 버튼
  - `/operator/new`: 투표 만들기(질문 + 선택지 2~10개, 입력칸 추가·삭제)
- **API(Route Handlers):**
  - `POST /api/polls`: 투표 생성(운영자만)
  - `DELETE /api/polls/[id]`: 투표 삭제(운영자만)
  - `POST /api/polls/[id]/vote`: 투표 행위. body는 `optionId`. 이미 투표한 브라우저면 표를 기록하지 않고 "이미 투표함"으로 응답해, 화면이 결과로 이동하게 한다.
  - `GET /api/polls/[id]/results`: 결과 조회. 결과 화면의 5초 폴링이 쓴다. 참여 쿠키가 있거나 운영자일 때만 응답한다.
  - `POST /api/login`, `POST /api/logout`: 운영자 세션 발급과 해제
- **운영자 인증:** 비밀번호가 `OPERATOR_PASSWORD`와 일치하면, `SESSION_SECRET`으로 서명한 세션 쿠키를 발급한다. 쿠키는 httpOnly, SameSite=Lax, 배포 환경에서는 Secure이고, 만료는 1일이다. 비밀번호 비교는 타이밍 차이가 나지 않는 방식으로 한다. `/operator` 경로는 Next.js Proxy로 로그인 화면에 보내는 가드를 두고, 운영자 전용 API도 각자 세션을 다시 검증한다. Proxy만 믿지 않는다.
- **투표자 참여 표시(ADR-0001):** 투표 행위가 성공하면 그 투표 전용 참여 쿠키(httpOnly)를 심는다. 쿠키는 마감이 없는 투표에 맞춰 길게(1년) 유지한다. 이 쿠키로 결과 열람 허용과 같은 브라우저의 재투표 차단을 함께 판단한다. 우회할 수 있는 약한 방지라는 점은 ADR-0001에 기록된 의도된 선택이다.
- **내 선택 표시:** 참여 쿠키의 값은 투표자가 고른 선택지 id다. 결과 화면은 그 선택지 칸을 초록색으로 강조하고 "✓ 내 선택"이라고 표시한다. 누가 무엇을 골랐는지는 투표자 자신의 브라우저에만 있고 DB에는 저장하지 않으므로 익명성은 유지된다. 투표하지 않고 결과를 보는 운영자에게는 표시가 없다.
- **결과 계산:** 비율은 득표수 ÷ 총 투표 수를 정수 %로 반올림한다. 총 투표 수가 0이면 모든 선택지를 0%로 표시한다. 선택지는 생성 시 입력한 순서로 보여준다.
- **실시간 갱신:** 결과 화면은 5초마다 결과 API를 다시 불러 숫자를 갱신한다. 화면을 떠나면 폴링을 멈춘다. WebSocket 같은 서버 푸시는 쓰지 않는다.
- **캐시:** 목록, 투표, 결과 화면은 항상 최신 DB 값을 보여줘야 한다. 생성·삭제·투표 직후 이전 값이 캐시로 남지 않게 한다.

## Testing Decisions

- **좋은 테스트의 기준:** 사용자가 겪는 외부 동작만 검증한다. 화면에 무엇이 보이는지, 어디로 이동하는지, 숫자가 어떻게 바뀌는지를 본다. 내부 함수 이름, SQL 문장, 컴포넌트 구조는 검증하지 않는다. 그래야 구현을 바꿔도 테스트가 깨지지 않는다.
- **테스트 경계(seam)는 하나:** Playwright 브라우저 E2E다. Playwright가 `npm run dev`로 앱을 띄우고, 실제 브라우저로 운영자와 투표자 흐름을 조작한다. 단위 테스트는 두지 않는다.
- **DB:** 별도 테스트 DB 없이 `.env.local`의 `DATABASE_URL`(사전 준비에서 만든 Neon DB)을 그대로 쓴다. 실제 데이터를 건드리지 않도록 규칙을 둔다.
  - 테스트는 자기가 만든 투표만 다룬다. 질문에 고유한 테스트 접두어를 붙인다.
  - 테스트가 끝나면 자기가 만든 투표만 삭제한다.
  - 테이블 전체를 비우는 동작은 하지 않는다.
  - 테스트는 테이블이 이미 만들어져 있다고 가정한다.
- **투표자 여러 명 흉내내기:** Playwright의 브라우저 컨텍스트를 새로 만들면 쿠키가 없는 "다른 사람"이 된다. 이것으로 여러 투표자, 재투표 차단, 결과 게이팅을 검증한다.
- **검증할 흐름:**
  - 운영자 로그인 성공과 실패, 비로그인 상태의 `/operator` 접근 시 로그인 화면으로 이동, 로그아웃
  - 투표 만들기: 정상 생성 후 목록 표시, 선택지 1개·11개·빈 칸·빈 질문 거부(화면과 API 직접 호출 모두)
  - 투표자 투표 후 결과 화면으로 이동, 득표수·비율·총 투표 수가 올바른지
  - 같은 브라우저 재방문 시 결과로 이동, 재제출 차단, 다른 브라우저 컨텍스트에서는 투표 가능
  - 투표하지 않은 브라우저의 결과 주소 접근 시 투표 화면으로 이동. 운영자는 결과 열람 가능
  - 결과 화면을 연 채로 다른 컨텍스트가 투표하면, 새로고침 없이 숫자가 갱신됨
  - 삭제 확인 후 목록에서 사라짐, 삭제된 투표 주소 접근 시 "찾을 수 없음" 안내
  - 비로그인 상태의 생성·삭제 API 직접 호출 거부
- **기존 테스트:** 저장소에 아직 테스트가 없다. 이번에 Playwright 설정과 첫 테스트를 새로 만든다.

## v1.1 추가 기능 (마감 시각, 결과 그래프, 제작자 이름)

수업 과제로 추가한 세 기능이다. 용어는 `CONTEXT.md`의 **마감 시각(Closing Time)**, **마감됨(Closed)**을 따른다.

### User Stories

47. 운영자로서, 투표를 만들 때 마감 시각을 반드시 정하고 싶다. 그래야 투표가 끝없이 열려 있지 않는다.
48. 운영자로서, 마감 시각은 지금 이후이고 지금부터 최대 7일 뒤까지만 고를 수 있어야 한다. 입력칸에는 기본으로 24시간 뒤가 채워져 있으면 좋겠다.
49. 운영자로서, 규칙을 벗어난 마감 시각(비었음, 지난 시각, 7일 초과)은 화면과 API 모두에서 거부되고 이유를 보고 싶다.
50. 운영자로서, 마감 시각 전이라도 운영자 목록에서 투표를 직접 마감하고 싶다. 실수하지 않도록 확인을 한 번 거친다.
51. 운영자로서, 직접 마감하면 마감 시각이 마감한 그 시각으로 바뀌어 목록에 보이면 좋겠다.
52. 운영자로서, 운영자 목록에서 투표마다 마감 시각과 "마감됨" 여부를 보고 싶다.
53. 투표자로서, 첫 화면 목록에서 투표마다 마감 시각을 보고, 마감된 투표에는 "마감됨" 표시를 보고 싶다. 마감된 투표도 목록에 남는다.
54. 투표자로서, 마감된 투표를 열면 투표 화면 대신 결과 화면으로 가고 싶다. 투표하지 않았어도 결과를 볼 수 있다.
55. 투표자로서, 마감된 투표에 (오래된 화면에서) 제출해도 표가 기록되지 않고 결과 화면으로 가면 좋겠다.
56. 투표자로서, 투표·결과 화면에서 마감 시각 또는 "마감됨"을 보고 싶다.
57. 투표자로서, 결과 화면에서 선택지별 득표 비율을 가로 막대 그래프로 보고 싶다. 숫자("3표 · 60%")와 "✓ 내 선택" 강조는 그대로 남는다.
58. 투표자로서, 결과가 5초마다 갱신될 때 막대 길이와 마감 상태도 함께 갱신되면 좋겠다.
59. 누구나, 모든 화면 맨 아래에서 "제작: 김민혁"을 보고 싶다.

### Implementation Decisions

- **스키마:** polls에 `closes_at timestamptz not null`을 추가한다. 기존 투표는 `created_at + 7일`로 채운다. 운영 중인 배포본과 새 코드가 섞이는 동안 깨지지 않도록 컬럼 기본값은 `now() + 7일`로 둔다. 앱 코드는 항상 값을 직접 넣는다. 마이그레이션 SQL은 저장소에 두고 Neon SQL Editor에서 사람이 실행한다.
- **마감 여부는 DB 시각으로 판단한다:** `closes_at <= now()`이면 마감됨. 앱 서버 시계에 기대지 않는다.
- **직접 마감:** 마감 시각을 `now()`로 덮어쓴다. 별도의 "직접 마감됨" 상태는 두지 않는다. 이미 마감된 투표는 바꾸지 않는다. API는 `POST /api/polls/[id]/close`(운영자만)이다.
- **생성 규칙:** 마감 시각은 ISO 문자열로 받는다. 서버 기준 `지금 < 마감 시각 ≤ 지금 + 7일`이어야 한다. 화면의 입력칸은 브라우저 로컬 시각의 날짜·시간 입력(`datetime-local`)이고, 최소·최대값을 같은 규칙으로 건다.
- **투표 행위 기록:** 득표 증가 SQL 한 문장 안에서 투표가 마감 전인지 함께 확인한다. 확인과 기록 사이에 마감되는 경우가 없게 한다.
- **결과 열람 규칙:** `투표했음 || 운영자 || 마감됨`. 결과 화면과 결과 API가 같은 함수 하나를 쓴다.
- **시각 표시:** 항상 한국 시간(Asia/Seoul)으로 "10월 3일 18:00" 형식이다. Vercel 서버는 UTC이므로 시간대를 명시한다.
- **그래프:** 그래프 라이브러리 없이, 결과 목록의 각 선택지 칸 아래에 비율만큼 채워진 가로 막대를 CSS로 그린다. 막대는 숫자와 같은 정보를 반복하므로 보조기기에서는 숨긴다. 내 선택은 초록색 막대다.
- **제작자 이름:** 루트 레이아웃의 푸터에 "제작: 김민혁"을 넣어 모든 화면에 보이게 한다.

### Testing Decisions

- 기존과 같이 Playwright E2E 하나의 경계에서 검증한다. 테스트용 투표 생성 도우미는 마감 시각을 기본 24시간 뒤로 보낸다.
- 시간이 지나 자동으로 마감되는 경우는 마감 시각을 몇 초 뒤로 잡고 실제로 기다려서 검증한다.
- 직접 마감은 운영자 화면의 버튼으로 검증한다.
